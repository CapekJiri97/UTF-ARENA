Virtual socket — překládá entity emit() volání do room broadcasts:


function makeVirtualSocket(io, roomName) {
  return {
    emit(event, data) {
      switch (event) {
        case 'host_event':    io.to(roomName).emit('network_host_event', data); break;
        case 'host_state':    io.to(roomName).emit('network_host_state', data); break;
        case 'broadcast_kill':io.to(roomName).emit('network_kill_feed',  data); break;
        case 'player_action': io.to(roomName).emit('network_player_action', data); break;
      }
    },
    broadcast: { to: () => ({ emit: () => {} }) },
  };
}

Update všech playerů (p.update(dt)) a minionů, projektilů, towers, healů, powerupů, speedpadů
Burn DoT tick pro playery a miniony
Player–player kolize (push), minion–minion kolize (spatial grid)
Pasivní příjem goldů (1s tick)

Jak to funguje end-to-end

Klient klikne Start Game
    → socket.emit('start_game')
    → Server: startServerGame() spustí loop
    → Server: io.emit('game_start', { hostId: '__server__' })
    → Klienti: game.isHost = false (socket.id !== '__server__')
    → Klienti: startGameNetworked() vytvoří lokální Player + bot placeholdery

Každých 50 ms (server):
    → _serverTick() — boti myslí, minioni bojují, towers střílí
    → _broadcastFast() → 'network_host_state' (bot pozice)
    → každých 125 ms: _broadcastSlow() → 'network_host_state' (full state)

Klient pohybuje hráčem:
    → socket.emit('player_update', { x, y, aimAngle })
    → Server: applyPlayerUpdate() aktualizuje pozici

Klient útočí / castuje spell:
    → socket.emit('player_action', { type: 'shoot'/'cast', tx, ty })
    → Server: handlePlayerAction() → p.shoot() / p.castSpell()
    → gc.applyDamage() → serverLogic.applyDamage() → broadcastuje show_damage + hp_update

Hráč umře:
    → gc.handlePlayerKill() → broadcastuje 'player_died'
    → Klienti: volají client-side handlePlayerKill() pro vizuální efekty (bez reward grantu)
Limitace Fáze 2
Jeden aktivní game per Node.js process — game singleton z State.js je globální. Multi-room podpora vyžaduje Worker Threads (Fáze 7).
Lidský hráč — pozice — server důvěřuje pozici klienta (anti-cheat = Fáze 6). Server jen přijímá player_update a přepisuje pozici.
Bez client-side prediction — při lagu se lokální hráč "trhá" zpět na serverovou pozici.
Fáze 2.5 — Opravy a zpevnění server autority
Co bylo uděláno

Bot roster synchronizace
ServerEngine.js — po spawnutí botů emituje io.to(roomName).emit('bot_roster', [...]) s autoritativním seznamem botů (id, team, className, lane, summonerSpell).
main.js startGameNetworked — odstraněna lokální randomizace botů. Klienti nespawňují boty sami.
main.js — přidán socket.on('bot_roster') handler, který spawňuje BotPlayer instance se správnými třídami ze serveru.

buyItem / sellItem — server autorita
Při server architektuře (!game.isHost): nejdříve emituj player_action na server, pak optimisticky aktualizuj lokálně pro okamžitou odezvu UI.
Odstraněna duplicitní aplikace buy/sell od jiných síťových hráčů v network_player_action handleru — server pošle aktualizaci přes _broadcastSlow.

_broadcastSlow humans — rozšíření
Přidána pole: towerDefends, towerAssaultTime, objectivePresenceTime, powerupsCollected, powerupUptime, pcsBreakdown, level, maxHp, items (slice), AD, AP, armor, mr, speed, attackSpeed, abilityHaste.
Klient v network_host_state zpracovává level-up animaci, items sync a stat sync pro ostatní síťové hráče.

server.js player_update — pořadí
applyPlayerUpdate() se volá před broadcast, aby server měl vždy nejnovější pozici před odesláním ostatním.

Fáze 3 — Combat autorita + opravy integrity
Co bylo uděláno

network_host_event: damage odstraněno z klienta
Klient (main.js) již nevykonává applyDamage při přijetí host_event type=damage.
Server posílá show_damage (vizuální efekty) + player_hp_update (autoritativní HP) — double-apply je tím eliminován.
Stará 'damage' větev v network_host_event handleru odstraněna.

revive() / die() guard
main.js: p.revive() a p.die() obaleny typeof guard (method existence check), aby klient nespadl pokud by server poslal alive/dead změnu dřív než je Player plně inicializován.

_broadcastSlow humans — stats pole
ServerEngine.js _broadcastSlow: přidáno stats: { dmgDealt, dmgTaken, hpHealed } pro každého lidského hráče.
Klient tato data přijímal ale server je neodesílal — scoreboard nyní zobrazuje správné combat statistiky.

Combat pipeline (verified):
Boti a minioni: Minion.update() / BotPlayer.update() → gc.applyDamage() → serverLogic.applyDamage() → show_damage + player_hp_update broadcast
Lidský hráč útočí: klient emituje player_action{type:'shoot'/'cast'} → server p.shoot()/p.castSpell() → gc.applyDamage() → broadcast
Tower damage: Tower.update() → gc.applyDamage() přímo na serveru → broadcast (server architektura nepotřebuje host_event:damage)

Fáze 4 — Vizuální feedback a cleanup klientské logiky
Co bylo uděláno

Lokální damage čísla pro vlastní útoky (klient)
applyDamage v main.js: rozšířena podmínka pro zobrazení DamageNumber — nyní se zobrazují i v server módu pokud je hráč zdrojem útoku (sourceId === player.id).
Díky tomu hráč vidí svá damage čísla okamžitě (bez čekání na síťové echo od serveru).
Podmínka pro particle efekty rozšířena stejně — blast particles se spawňují lokálně při vlastním útoku.

Odstraněn mrtvý host_event: damage emit
V applyDamage: odstraněn blok `if (socket && game.isHost)` který posílal host_event type='damage' pro minion → player damage.
V server architektuře server posílá player_hp_update přímo — tento kód byl nikdy nespuštěný remnant z host-client éry.

player_disconnected — playersById rebuild
socket.on('player_disconnected'): po odebrání hráče z game.players se přestaví game.playersById Map.
Bez toho by O(1) lookup vrátil stale / undefined pro odpojeného hráče.

Minion _syncDirty při HP změně
ServerGameLogic.js applyDamage: při každém HP snížení miniona se nastaví m._syncDirty = true.
Bez toho klient dostal HP update minionů pouze jednou (při spawnu) a pak zobrazoval vždy 100% HP.
Entities.js Minion.update: při ARAM retargetingu (targetIndex změna) se nastaví _syncDirty = true, klient pak ví o novém cíli miniona.

Fáze 6 — Client-side prediction (lehká)
Cíl: Lokální hráč se pohybuje okamžitě bez pocitu lagu. Server posílá autoritativní korekci pozice.

Co bylo uděláno:

ServerEngine.js — _broadcastSlow humans: přidáno x, y (Math.round) do human broadcast
ServerEngine.js — applyPlayerUpdate: ignoruje klientovu pozici pokud server právě aplikuje knockback/stun/dash (server je autorita)
ServerEngine.js — _broadcastFast: přidána sekce humanPosCorrections — rychlé korekce pozice pro hráče se serverem řízenou fyziku (knockback, stun, dash) — posílá se 20 Hz
main.js — network_host_state: zpracování humanPosCorrections — okamžitý snap pozice hráče (bez lerp, protože jde o knockback)
main.js — network_host_state humans: při přijetí serverové pozice lokálního hráče:
  - rozdíl > 150px → okamžitý snap (teleport/respawn)
  - rozdíl 30–150px → smooth lerp přes p._serverPosTarget
  - rozdíl < 30px → ignorovat (lokální predikce je dostatečně přesná)
main.js — game loop: každý frame aplikuje smooth lerp k p._serverPosTarget pokud je nastaven (lerpRate = 1 - 0.05^dt, konverguje za ~0.25s)
  - Lerp se přeskočí pokud má hráč stunTimer > 0 nebo knockbackTimer > 0 (server posílá fast korekci přes humanPosCorrections)
main.js — player_died + revive: vyčistí p._serverPosTarget aby nedošlo k lerpování na stale korekci

Výsledek:
Pohyb lokálního hráče je vždy okamžitý (nečeká na server).
Knockback ze serveru je okamžitě snapped přes humanPosCorrections (20 Hz).
Malé drift korekce jsou smooth (žádný "trhavý" pohyb).

Fáze 7 — Cleanup & Multi-room
Cíl: Odstranit mrtvý kód z host-client éry a umožnit paralelní běh více herních místností na jednom Node.js procesu.

Part 1 — Cleanup (main.js):
Odstraněny 3 mrtvé `if (socket && game.isHost)` bloky z main.js:
  - applyDamage: emit show_damage → server broadcastuje sám přes network_host_event
  - applyDamage: emit player_hp_update → server broadcastuje sám přes _broadcastSlow
  - handlePlayerKill: emit player_died → server broadcastuje sám přes network_host_event
Odstraněn celý blok "HOST SYNCHRONIZUJE STAV BOTŮ A MINIONŮ" (~70 řádků) z update() v main.js:
  - `if (game.isHost)` blok s hostSyncTimer + hostSlowSyncTimer posílal host_state/host_state
  - V server architektuře toto dělá ServerEngine._broadcastFast() + _broadcastSlow() přímo
  - game.isHost je vždy false na klientech (hostId: '__server__') — celý blok byl dead code

Part 2 — Multi-room (ServerEngine.js):
Nahrazeny globální singletony `_activeRoom`, `_activeInterval`, `_activeMode` za `_rooms` Map:
  - _rooms: roomName → { interval, mode, vSocket, serverLogic, state }
  - Každá room má svůj vlastní game state objekt (state), izolovaný od ostatních rooms
Context-swap vzor (_withRoomContext):
  - Před každým tickem: zkopíruje room state do globálního `game` singletonu + swapne gc.socket/activeGameMode/serverLogic
  - Po ticku: zkopíruje zpět z `game` do room state
  - Důvod: Player.js, GameMode_*.js, Entities.js importují `game` přímo z State.js — bez refaktoru všech souborů nelze předat per-room stav jako parametr. Context swap je O(n_keys) na tick, prakticky nulová overhead.
Signatury změněny (server.js aktualizován):
  - handlePlayerAction(roomName, playerId, data)
  - removePlayerFromGame(roomName, playerId)
  - applyPlayerUpdate(roomName, playerId, data)
Bot ID uniq: bot0_1_roomName (přidán roomName suffix) — zamezí kolizi ID botů across rooms

Part 3 — Final dead-code cleanup:
Odstraněny zbývající mrtvé kusy z host-client éry:
  - main.js applyHeal(): 2 mrtvé emit řádky (`show_heal`, `player_hp_update`) — v server módu gc.applyHeal = serverLogic.applyHeal (jiná funkce), v offline módu socket === null
  - server.js: 2 mrtvé passthrough handlery `socket.on('host_state', ...)` a `socket.on('host_event', ...)` — klienti tyto eventy nikdy neposílají v server-authoritative módu; ServerEngine broadcastuje přímo přes vSocket/io.to()
